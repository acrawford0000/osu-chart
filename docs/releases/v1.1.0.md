# osu!Chart v1.1.0

A refreshed Windows desktop release for comparing osu! player progress.

## Download

- **Portable executable:** download `osu-chart-v1.1.0-windows-amd64.exe` and run it.
- **ZIP package:** download `osu-chart-v1.1.0-windows-amd64.zip`, extract it, and run `osu-chart.exe`. The ZIP includes the license and a short setup guide.
- **Checksums:** `SHA256SUMS.txt` lists SHA-256 hashes for both downloads.

Windows x64 and Microsoft Edge WebView2 Runtime are required. The Microsoft WebView2 bootstrap installer is embedded for systems without the runtime. Go, Node.js, and Wails are not needed to run the app. This build is unsigned.

## What changed

- A consistent charcoal-and-violet theme, responsive navigation, refreshed player cards, and clearer settings.
- Thirteen readable metrics grouped into Performance, Activity, Grades, and Hit Results. Score totals serialized as strings now plot correctly.
- A tooltip that independently finds the closest saved observation for every visible player, with each observation's actual date.
- A global-rank axis that puts improving rank higher on the chart.
- A more efficient contact-page parallax effect that settles while idle and respects reduced-motion preferences.
- Independent loading, retry, and error states; stale responses cannot overwrite newer game-mode selections or restore removed players.
- Credential changes are validated before saving, preserving the previous working configuration on failure.
- Credentials use the operating system's configuration directory; broad file serving and debug data dumps have been removed.
- API timeouts, checked HTTP responses, and clearer recoverable errors.

## Setup

Open **Settings**, enter your osu! OAuth application credentials, and select **Save credentials**. Add players on **Players**, then open **Chart**. Existing project-folder credential files are imported automatically without deleting the original copy.

[See screenshots and full documentation](https://github.com/acrawford0000/osu-chart#screenshots).

## Known development issue

The existing Svelte 3 / router type-declaration mismatch still causes five errors in `npm run check`. Production builds and runtime navigation have been verified. This does not require any action when running the Windows release.
